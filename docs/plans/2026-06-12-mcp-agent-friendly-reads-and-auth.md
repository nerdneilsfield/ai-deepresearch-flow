# MCP Agent-Friendly Reads + Split Auth Entrypoints Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

## Overview

Implement the design in `docs/plans/2026-06-12-mcp-agent-friendly-reads-and-auth-design.md`:

- replace full-content MCP readers with granular content outline/window tools
- keep summary reads key-oriented and bounded
- remove full-content MCP resources and resource templates from the public MCP surface
- split static bearer MCP entrypoints from GitHub OAuth entrypoints
- keep static bearer `/mcp` and `/mcp-sse` usable in OAuth mode
- target `/oauth/mcp` for OAuth streamable HTTP and gate `/oauth/mcp-sse` behind a transport spike

## Constraints

- Follow AGENTS black-box testing policy.
- Do not assert private registries, route-table internals, implementation branches, regex internals, or parser internals.
- Public MCP behavior must be tested through public MCP protocol calls where feasible.
- Helper tests may target declared helper contracts by module path, function name, parameter types, return type, and public input/output behavior only.
- Existing HTTP API behavior outside MCP must remain unchanged.
- No database migration.
- MCP/snapshot tests live under `python/deepresearch_flow/paper/snapshot/tests/`; do not place new MCP tests only under root `tests/` unless matching existing project layout requires it.
- If OAuth SSE cannot be proven without compromising static SSE, stop and ask for user approval before shipping a three-entrypoint variant.

## Phase 2: Granular content window helpers

### Task 2.1: Add line-window helper contract

Files:

- `python/deepresearch_flow/paper/snapshot/mcp_content.py`
- tests in `python/deepresearch_flow/paper/snapshot/tests/test_mcp_content.py` or a sibling snapshot test module

Public helper contract:

- Module: `deepresearch_flow.paper.snapshot.mcp_content`
- Function: `compute_content_window` or equivalent named public helper for computing bounded content windows from text.
- Inputs: markdown/text string, mode, optional line parameters, line budgets, character budgets. Recommended budgets are `500` lines per range, `800` total lines, `12_000` characters per range, and `24_000` total characters.
- Output: dictionary/model with total line count, selected ranges, truncation flags, and bounded content.
- Behavior: exactly as specified in the design doc.

Tests, black-box input/output only:

- `head` returns the first requested lines within budget and clamps short documents to document length.
- `tail` returns the last requested lines within budget and clamps short documents to document length.
- `head_tail` merges overlapping/touching ranges; `truncated=false` only when the merged range covers the full document; total char budget is enforced across ranges.
- `range` requires start/end inside `1..total_lines`, rejects invalid or oversized ranges, and never silently clips explicit ranges.
- `around` includes center line, accepts zero before/after, clamps computed bounds, rejects center outside document.
- bool, string, float, zero, negative, irrelevant mode parameters, and excessive counts are rejected with the expected public error code.
- a huge single line is character-truncated with `truncated_by_chars=true`.
- empty markdown/text is rejected with the documented public error code.
- `invalid_window_mode`, `invalid_line_range`, `invalid_line_count`, and `window_too_large` are covered by public input/output assertions.

## Phase 3: Summary key/value bounded reads

### Task 3.1: Harden summary key discovery

Files:

- `python/deepresearch_flow/paper/snapshot/mcp_content.py`
- `python/deepresearch_flow/paper/snapshot/mcp_server.py`

Behavior:

- `get_paper_summary_keys` accepts `max_depth`, `include_preview`, and `max_paths`.
- `max_depth` must be an actual int in `0..4`.
- `include_preview` must be an actual bool.
- `max_paths` must be an actual positive int, default `200`, hard cap `500`.
- preview total budget defaults to `4_000` characters.
- key path strings are capped at `512` characters per path and `16_000` total path characters.
- output indicates truncation when paths/previews are capped and includes enough public counts for agents to refine requests.

Tests:

- bounded key discovery returns expected public paths for representative nested objects/arrays.
- invalid scalar types are rejected.
- large arrays/objects are capped and report truncation.
- previews and key paths do not exceed advertised budgets.
- `template_not_available` is covered as a public error.
- no test depends on traversal implementation, recursion order beyond documented output order, or parser internals.

### Task 3.2: Rename keyed read tool to `get_paper_summary_value`

Files:

- `python/deepresearch_flow/paper/snapshot/mcp_server.py`
- `python/deepresearch_flow/paper/snapshot/mcp_content.py`

Behavior:

- Stop registering `get_paper_summary_key` as an MCP tool.
- Register `get_paper_summary_value`.
- Preserve simple key grammar behavior for field paths and array indexes.
- Reject `$` root selector.
- Scalar/string values return only the selected value subject to `max_chars`; default `4_000`, hard cap `16_000`.
- `include_subtree` must be an actual boolean.
- Object/array values return metadata and bounded child keys by default: child key count default/hard cap `100/300`, per-child-key budget `256`, total child-key budget `8_000`, with `child_count`, `returned_child_keys`, and `children_truncated`.
- `include_subtree=true` returns compact JSON for the selected subtree only, capped by `max_chars`.
- If compact JSON is truncated, return it as plain text with `content_format="text/plain"`, `content_is_valid_json=false`, and `truncated=true`; untruncated JSON uses `content_format="application/json"` and `content_is_valid_json=true`.

Tests:

- selected scalar/string value is returned without unrelated sibling content.
- selected object/array defaults to metadata and bounded child keys.
- child key caps are reported.
- `include_subtree=true` is capped and does not include unrelated siblings.
- `$` is rejected.
- bool/string/float invalid numeric parameters are rejected.
- `summary_key_not_found`, `template_not_available`, and `invalid_summary_key` are covered as public errors.

- valid static token rejected on `/oauth/mcp`.
- A non-static bearer token, including a locally controlled fake/stub OAuth-looking token, is rejected on `/mcp` without real GitHub/network calls unless it exactly equals the static token and is treated as static bearer auth.
- missing auth on static endpoints returns static bearer challenge, not GitHub redirect/challenge.
- missing auth on OAuth endpoints returns OAuth challenge for `{base}/oauth/mcp`.

## Parallelization Guidance

Recommended lanes for subagent implementation after the plan is approved:

- Transport/auth lane: Phase 1 and Phase 5. Owns `api.py`, `auth.py`, transport tests, route matrix, and only the app factory/auth/app creation areas of `mcp_server.py`.
- Content window/outline lane: Phase 2. Owns `mcp_content.py` content-window helpers and content tests; avoid `mcp_server.py` registration edits.
- Summary lane: Phase 3. Owns summary helper behavior in `mcp_content.py` and summary tests; avoid `mcp_server.py` registration edits.
- MCP registration/resources lane: Phase 4. Depends on Phase 2/3 helper contracts and owns tool/resource registration edits in `mcp_server.py`; coordinate with transport lane before touching app factory/auth creation areas.
- Docs lane: Phase 6. Starts after route/tool names stabilize.

Merge points:

- Phase 4 should not start until content and summary tool contracts are implemented or stubbed.
- Docs should not finalize until OAuth SSE support status is known.
- If OAuth SSE gate fails, continue independent read/summary work but do not mark auth complete until user chooses fallback.
